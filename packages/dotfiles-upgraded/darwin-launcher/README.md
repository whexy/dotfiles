# Signed Darwin updater launcher

`Dotfiles Updater.app` is the stable, root-owned TCC identity for unattended
switches. It launches only `/run/current-system/sw/bin/dotfiles-upgraded-service`,
waits for that child, and reloads the entrypoint after it exits. It accepts no
command or flake arguments and exposes no privileged socket.

The service entrypoint is generated by `modules/hosts/system/darwin.nix`. It runs
the CI-gated updater with `--exit-after-switch`: after recording a successful
switch, the updater exits so the launcher picks up the new system's binary and
configuration. Failed and pending candidates retain the ordinary retry and
polling behavior. Launchd's plist contains no Nix-store paths, preventing normal
package upgrades from unloading the process performing activation.

## One-time setup

1. Build with a persistent signing identity available in your login Keychain:

   ```sh
   security find-identity -v -p codesigning
   bash packages/dotfiles-upgraded/darwin-launcher/build.sh \
     /tmp/dotfiles-updater-production SIGNING_IDENTITY_HASH
   ```

2. Install the app as root (do not symlink it into a user-writable checkout):

   ```sh
   sudo ditto '/tmp/dotfiles-updater-production/Dotfiles Updater.app' \
     '/Applications/Dotfiles Updater.app'
   sudo chown -R root:wheel '/Applications/Dotfiles Updater.app'
   sudo chmod -R go-w '/Applications/Dotfiles Updater.app'
   codesign --verify --strict '/Applications/Dotfiles Updater.app'
   ```

3. Add **Dotfiles Updater.app** to Full Disk Access in System Settings and enable
   it. This is a different identity from **Dotfiles Updater Probe**; the probe's
   grant does not transfer. No Bash or Nix FDA grants are required by the tested
   process chain.

4. Enable `dotfiles.system.autoUpgrade.enable` for the host. **Publish this
   configuration to the tracked upstream and let CI pass before starting the
   daemon.** Otherwise it can immediately converge back to an older upstream
   configuration which disables the service. Signing keys and the installed app
   are local bootstrap assets, not part of the public flake or CI build.

5. Build and perform one authenticated bootstrap switch:

   ```sh
   nix build .#darwinConfigurations.golf.system --out-link /tmp/golf-bootstrap
   sudo /tmp/golf-bootstrap/sw/bin/darwin-rebuild switch --flake .#golf
   ```

   Thereafter the root LaunchDaemon polls upstream and switches without sudo
   prompts. The initial foreground switch may still need your terminal's privacy
   access; it is not evidence of the daemon's FDA attribution. Verify a subsequent
   daemon-driven switch through its log.

## Observe and recover

```sh
launchctl print system/org.nixos.dotfiles-upgraded
tail -n 80 /var/log/dotfiles-upgraded.log
jq . /var/lib/dotfiles-upgraded/status.json
```

A log entry `switched` and matching `lastSuccessSha` in status are the success
criteria, not merely a running service. Previous failed commits remain ignored;
a new pushed commit becomes a new candidate. An empty error alone does not
establish that a switch succeeded.

To stop the service explicitly:

```sh
sudo launchctl bootout system/org.nixos.dotfiles-upgraded
```

To start it again:

```sh
sudo launchctl bootstrap system /Library/LaunchDaemons/org.nixos.dotfiles-upgraded.plist
```

Changing the launchd plist or disabling auto-upgrade from an unattended switch
can still unload the active job. Make those lifecycle changes through an
interactive maintenance switch. Normal updates change only the Nix-managed
entrypoint and daemon, not the plist or signed launcher.

The native launcher intentionally stays outside Nix's changing store paths.
Updating it requires an explicit signed replacement while the daemon is stopped.
Certificate renewal, other macOS versions, and full activation must be validated
separately from the successful FDA probe. There is no unauthenticated arbitrary
local-flake activation endpoint; routine updates follow the configured upstream
and existing CI gate.
