# 6. Threat model

## Assets

| Asset                                                        | Where it lives in the proposed design                                  |
| ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Owner's personal identity and keys (SSH, signing, 1Password) | Owner devices only. Never in the image or sandbox                      |
| agenix master identity and the 15 secrets                    | Owner hosts. Never in the image or sandbox                             |
| GitHub App private key                                       | Broker only (agenix, dedicated recipient)                              |
| Installation tokens                                          | Broker or Git proxy. 1 h, one repo                                     |
| Model API keys                                               | n8n or AI proxy                                                        |
| Sandbox tenant API key                                       | n8n credential store                                                   |
| Runner mTLS CA and keys                                      | Cluster Secrets for the service                                        |
| Source code of target repos                                  | Sandbox (task-scoped), GitHub                                          |
| Private infrastructure (tailnet, cluster, LAN)               | Unreachable from sandboxes, except through proxy allowlists in stage 4 |

## Adversaries

The two protection goals differ, so they are listed separately.

**A. External attackers.** Someone who reaches the Sandbox API, runner or
n8n from outside, or who ships a compromised image, dependency or flake.
Controls: authentication, network placement, patching and pinning.

**B. The agent itself.** A misaligned agent, or one goal-hijacked by injected
content: repo files, issues, web pages, dependency output (OWASP Agentic
ASI01 goal hijack, ASI02 tool misuse, ASI03 privilege abuse
[D](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/);
MITRE ATLAS AML.T0051.001 indirect prompt injection, AML.T0086 exfiltration
via agent tool invocation [D](https://github.com/mitre-atlas/atlas-data)).
It has **legitimate** code execution, so isolation does not stop it from
misusing what it is given. The controls are least privilege on data,
credentials and egress, plus human review.

The "lethal trifecta" (private data, untrusted content, external
communication) [D](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)
applies to every `public`-egress sandbox that reads untrusted repositories.
This design removes the private-data leg: the sandbox holds no secrets.
`egress: none` removes the communication leg where possible.

## Residual risks

Risks that remain after all proposed mitigations, for the owner to accept or
reject:

1. **Shared kernel.** Sysbox narrows but does not remove kernel attack
   surface. A kernel 0-day compromises the runner and, per n8n's security
   model, the fleet. Only a microVM runtime (Firecracker, which needs an
   Enterprise licence for production, or Kata) would change this.
2. **Review is the control for code content.** Agents produce
   attacker-influenced code by design. The PR diff is the product and the
   attack surface at once.
3. **Allowed egress is an exfiltration channel.** Every allowed host (package
   registries, caches) can carry low-bandwidth exfiltration. The design keeps
   sandboxes free of anything worth exfiltrating, apart from the target repo.
4. **Stage 3 session tokens are usable, not just readable.** Within proxy
   policy, the agent can push to its own branch and open PRs. That is the
   intended capability, not a leak.
5. **The orchestrator is trusted.** n8n holds the tenant key and can read and
   write every sandbox file. A compromise of n8n equals a compromise of every
   sandbox and every in-flight task.
6. **Unverified inferences.** DNS-path leakage, Sysbox + PVC ownership, the
   cluster's CNI, and tailnet-lock compatibility with the operator all need
   the PoC tests before being relied on.
7. **Existing dev hosts are out of scope.** Agents there run as the owner
   with access to the agenix identity. This design does not improve that. A
   separate follow-up could run host agents under a dedicated uid.
